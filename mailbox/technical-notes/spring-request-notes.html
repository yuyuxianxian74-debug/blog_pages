一次请求的旅程：理解 Spring 的分层 ​

2026.10.31 · Java & Spring · 示例文章

这是一篇说明博客代码块、表格与提示框样式的示例。用“查询一条笔记”作为场景，可以直观地理解分层。

每一层负责什么 ​

层次 主要职责 示例
Controller 接收请求、校验输入、组织响应 接收笔记 ID
Service 编排业务规则 检查笔记是否可见
Mapper 读写持久化数据 按 ID 查询记录

请求入口 ​

java
@RestController
@RequestMapping("/notes")
public class NoteController {
    private final NoteService noteService;

    public NoteController(NoteService noteService) {
        this.noteService = noteService;
    }

    @GetMapping("/{id}")
    public Note findById(@PathVariable Long id) {
        return noteService.findById(id);
    }
}

这段代码仅用于展示入口结构，Note 和 NoteService 需要在实际项目中实现。业务判断应该在 Service 中完成。

排查问题时沿着调用链走 ​

如果接口没有返回预期数据，可以依次确认路由是否命中、参数是否正确、业务分支是否执行，以及 SQL 和数据库中的数据是否一致。

留下证据

完整异常、请求参数与实际 SQL，通常比编辑器里的单条警告更能说明问题。
