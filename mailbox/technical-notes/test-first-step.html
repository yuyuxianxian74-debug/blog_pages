从一个接口开始，练习测试思维 ​

2026.10.30 · 测试开发 · 示例文章

测试一个查询接口时，成功返回只是开始。接下来，可以把输入、权限、数据状态分别展开。

先写清楚预期 ​

假设接口为 GET /notes/{id}，下面是一组示例检查点。实际状态码应以项目接口契约为准。

场景 示例预期
存在且公开的笔记 返回 200 和对应记录
不存在的 ID 返回约定的未找到响应
不合法的参数 返回约定的参数错误
无权限的私有笔记 拒绝读取，不泄露正文

让验证可以重复 ​

js
// 示例：在 Node.js 中请求接口；请替换为实际运行的服务地址。
const response = await fetch('http://localhost:8080/notes/1')
console.log(response.status)
console.log(await response.json())

不止检查状态码 ​

还应检查响应字段、数据类型、内容是否对应请求，以及查询是否产生了意外的数据变更。

把一次临时检查沉淀成固定步骤，才更容易在后续修改中发现回归。
